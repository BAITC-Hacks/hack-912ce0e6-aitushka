# AI-помощник аналитика

Помощник объясняет уже рассчитанные показатели и найденные события. Он не классифицирует клиентов заново, не меняет приоритет и не делает вывод о виновности. Ответ — черновик для проверки аналитиком.

## Сценарий использования

1. Откройте карточку клиента и нажмите «Объяснить клиента».
2. Прочитайте наблюдения, возможное объяснение, неизвестные обстоятельства и следующие шаги.
3. Нажмите ссылку F возле утверждения: откроются показатели, на которые ссылается модель. Для источника-события доступен переход на граф.
4. Задайте вопрос по текущему клиенту или нажмите «Подготовить заключение». Вопросы независимы: переписка из прошлых ответов не передаётся.
5. «Скачать с основаниями» сохраняет TXT с ответом, моделью, fingerprint и исходными основаниями.
6. Для разбора конкретного события раскройте его в блоке «События и маршруты» и нажмите «Объяснить событие».

Открытие страницы само по себе не вызывает модель. Отмена ожидания останавливает ожидание в браузере, но уже отправленный запрос OpenAI может завершиться и расходовать средства.

## Настройка

Локальный `.env` находится в корне проекта. Шаблон — `.env.example`:

```dotenv
OPENAI_API_KEY=YOUR_KEY_HERE
OPENAI_MODEL=gpt-5.4-mini
AI_MAX_REQUESTS=50
```

Переменные окружения процесса имеют приоритет над файлом. Ключ не передаётся браузеру и не сохраняется в ответах. После установки зависимостей обычный запуск: `python run.py --data data --out outputs --ui` (используйте Python из `.venv`). Для AI дополнительно нужен сетевой доступ к `https://api.openai.com/v1/responses` и доступ к выбранной модели.

`AI_MAX_REQUESTS` ограничен диапазоном 1–500; счётчик действует на один процесс backend и сбрасывается при перезапуске. Неуспешные попытки тоже учитываются. Дополнительно: максимум 10 попыток в минуту и 2 одновременно. Повтор уже выполняющегося запроса отклоняется. Кеш содержит до 100 ответов на 30 минут; идентичный запрос из кеша не вызывает OpenAI. Для нескольких процессов лимиты не суммируются — это локальный MVP, не общий финансовый бюджет. Автоматических повторов нет.

## Какие данные уходят в OpenAI

Backend формирует пакет из текущего AnalysisResult: период и ограничения выборки, роль и вклады в приоритет, готовые суммы и количества, пять крупнейших контрагентов каждого направления, до 62 активных дней и до 12 событий разных типов. Для выбранного события передаётся только оно с общим контекстом клиента. В событии ограничены повторяющиеся измерения (8) и эпизоды (4); их полные количества сохраняются. Добавление событий останавливается при достижении порога около 42 тысяч символов. Сокращения обозначены явно.

Исходные идентификаторы заменяются обозначениями «Участник_1» и т. п.; словарь остаётся локальным. Только участники переданного контекста могут быть восстановлены в ответе. Неизвестные идентификаторы в вопросе заменяются общим обозначением. Вопрос передаётся текстом: не вставляйте в него персональные сведения или секреты. Даты и суммы сохраняются; такая замена идентификаторов не обеспечивает полную анонимность.

Используется Responses API со Structured Outputs, `store: false`, без инструментов и доступа модели к файлам или БД. `store: false` отключает хранение ответа для последующего получения через API; это не заявление об отсутствии всех видов хранения у провайдера.

## Контракт и ограничения проверки

`POST /api/clients/{gid}/ai` принимает JSON:

```json
{"fingerprint":"64-символьная контрольная сумма текущего расчёта", "mode":"explain", "question":"", "pattern_id":null}
```

Режимы: `explain`, `question`, `brief`. Для question нужен непустой вопрос до 1500 символов. fingerprint берётся из текущего API-расчёта. Устаревшая версия возвращает 409, неизвестный клиент/событие — 404. Проверка fingerprint повторяется после генерации. Событие должно относиться к выбранному клиенту.

Ответ содержит `answer` (наблюдения, гипотезы, ограничения, шаги и признак недостатка данных), `sources`, `scope`, `fingerprint`, `gid`, `model`, `prompt_version`, `cached`, `created_at`, счётчики токенов `usage`. Каждое утверждение содержит текст и ссылки `refs` на F-источники. Сервер проверяет структуру, существование источников и допустимость обозначений участников. Текст выводится как обычный React-текст, без выполнения HTML.

Наличие корректной ссылки не доказывает, что модель верно поняла источник. Семантическая достоверность каждого вывода автоматически не гарантируется. Арифметика остаётся в Python, а инструкции модели запрещают придумывать числа и складывать объёмы разных шагов. Отдельной размеченной оценки качества на десятках кейсов пока нет.

При ошибке ключа, сети, таймауте, лимите, отказе модели или некорректном ответе показывается объяснение ошибки. HTML-справка и локальные основания доступны без AI; ошибочный ответ не заменяется имитацией генерации. Endpoint рассчитан на локальный запуск на loopback; для многопользовательского размещения нужны аутентификация, общий бюджет и отдельная политика доступа.

## Проверки

`tests/test_ai.py` выполняется без сети и реального ключа: подмена провайдера проверяет псевдонимизацию, сверку дневных сумм, область события, кеш, версию данных, лимиты, ошибки, формат Responses API и HTTP-контракт. Запуск: `python -m pytest tests/test_ai.py -q`.
